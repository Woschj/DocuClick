# /loop-Anleitung: lokaler Agent-Loop

Wird pro `/loop`-Iteration ausgefuehrt. Ziel: das lokale Modell (LM Studio) soll die
Test-Infrastruktur bauen und Bugs fixen; du greifst nur bei Eskalation oder
Stichproben-Review ein, um Claude-Tokens zu sparen.

1. Fuehre `powershell tools/local-agent-loop/orchestrator.ps1` aus.
   - Exit 0: keine offenen/eskalierten Tasks. Weiter mit Schritt 4.
   - Exit 1: es gibt noch offene (pending) Tasks, aber keine Eskalationen -> naechste
     Iteration einfach den Orchestrator erneut laufen lassen (nichts fuer dich zu tun).
   - Exit 2: es gibt Eskalationen -> weiter mit Schritt 2.

2. Fuer jede Datei unter `tools/local-agent-loop/escalation/*.md`:
   - Lies die Datei (Task-Beschreibung, alle Attempt-Zusammenfassungen, letzter Fehler).
   - Entscheide: entweder behebst du das zugrunde liegende Problem direkt im
     Quellcode (echter Claude-Edit, nur wenn der Task offensichtlich zu schwer/mehrdeutig
     fuer das lokale Modell war), ODER du vereinfachst/teilst den Task in
     `tools/local-agent-loop/tasks.json` in kleinere Schritte auf.
   - Setze den Task-Status in `tasks.json` zurueck auf `"pending"` und leere `attempts`.
   - Loesche die Handoff-Datei.

3. Fuer jede Datei unter `tools/local-agent-loop/spot-review/*.diff`:
   - Sieh dir das Diff an. Unauffaellig (entspricht der Task-Beschreibung, keine
     Sicherheitsprobleme, kein Scope-Creep) -> Datei einfach loeschen (Review "bestanden").
   - Auffaellig -> leg einen neuen Korrektur-Task in `tasks.json` an, der das Problem
     beschreibt, und loesche danach die Review-Datei.

4. Wenn `tasks.json` keine offenen/eskalierten Tasks mehr hat, pruefe zusaetzlich
   `tools/ai-test-loop/test-results/latest.json` (falls vorhanden):
   - `allDone == true` (alle Szenarien 2x in Folge PASS) -> Loop erfolgreich beenden,
     Erfolg melden.
   - Sonst: `tools/ai-test-loop/orchestrator.ps1` erzeugt bei FAIL automatisch neue
     Bugfix-Tasks in `tasks.json` (zweite Welle) -> naechste Iteration arbeitet die
     lokal weiter ab, kein Eingriff noetig ausser die Tasks landen selbst in Eskalation.

Nutze grosszuegige `/loop`-Intervalle (z.B. 10 Minuten), da ein Durchlauf einen
Release-Build und bis zu 12 UI-Szenarien umfassen kann.
